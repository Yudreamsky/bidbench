# bidbench 投标图纸工作台

面向 AI agent 的投标图纸数据底座，配一个本地可视化工作台。MVP 重点解决两类最容易出错的问题：

- **缺漏图纸**：目录对账、引用悬空、编号断号（同一百位段里连缺 3 张以内，分段编号之间的空档不算）、楼层覆盖、藏在内层压缩包或加密包里的图
- **误用旧版本图纸**：逐张图判断现行版，识别“改图不升版”，目录写的版次比手上的新时报警，建模任务锁定图纸基线并在升版时提醒

> 识别有三种执行器，输出格式相同（`bidbench/spec/schema.json`），可以随时替换：
> - **Claude 执行器**（内置）：调用 Claude 多模态识别，分经济、强两档，见下文“图纸识别”
> - **外部 agent**：把识别任务包交给 Codex 等 agent 的目标模式，见 [docs/外部执行器.md](docs/外部执行器.md)
> - **模拟执行器**：只读 PDF 文字层、按规则抽取，用于演示和测试，扫描件无法识别

## 安装（Windows）

到 [发布页](https://github.com/Yudreamsky/bidbench/releases) 下载最新的 `bidbench-setup-b*.exe`，双击安装，
开始菜单里打开“投标图纸工作台”。这是一个独立窗口，收图、识别、导出、设置都在里面点按钮完成；
有新版本时点“更新并重启”就能升级。详见 [docs/安装与更新.md](docs/安装与更新.md)。

下面是源码版的用法（开发、或在 macOS / Linux 上用）。

## 快速体验

```bash
pip install -e ".[dev]"
./samples/run_demo.sh demo-project      # 生成 5 批合成图纸（4 个压缩包 + 1 个文件夹），逐批收图、识别、计算
bidbench -p demo-project serve          # 浏览器打开 http://127.0.0.1:8765/
bidbench -p demo-project desktop        # 或者开独立窗口（需要 pip install -e ".[desktop]"）
```

演示只用合成数据和模拟执行器，不联网、不调用 Codex 和 Claude：设置放在项目旁边的 `demo-project.config` 里，
不动本机的设置和“最近项目”。

图多时的效果可以用 `python samples/make_big_sample.py <目录> 90` 生成一个约 950 张图的超高层合成项目来看（用模拟执行器识别）。

演示数据覆盖：目录列出但缺失的图、引用不存在的图、合订本、整套重发中消失的图、内层压缩包补来的图、加密压缩包、
同版次不同内容、设计变更单、GBK 文件名的压缩包、事实冲突（地上层数 20 / 21）、建模基线过期、
目录与收图版次不符（目录写建施-06 B 版、手上只有 A 版；结构目录没跟着升版）、
风险文件（acad.lsp、双扩展名程序、带宏的表格、带脚本的 PDF，内容都是无害的占位）、
直接给文件夹的补图（夹着压缩包、系统缩略图缓存和 Office 临时锁文件）。

## 日常用法

```bash
bidbench init 项目目录 --name "某某项目"
cd 项目目录
bidbench receive ~/下载/投标图纸0915.zip --date 2026-09-15   # 每收到一批图纸就登记一次
bidbench receive D:/共享盘/1020补充 --date 2026-10-20         # 也可以是一个文件夹（连子文件夹一起收）
bidbench receive 建筑.zip 结构.zip 说明.pdf --date 2026-10-21  # 或同一次收到的几个文件，算同一批
bidbench tasks                                               # 生成识别任务包，交给外部 agent
bidbench import recognition/tasks/<任务包>/results           # 校验并导入识别结果
bidbench recognize                                           # 或：用模拟执行器直接识别并导入
bidbench build                                               # 计算台账、缺图、事实层，写报告
bidbench baseline "3层结构模型" --sheets 结施-01,结施-04     # 开始建模前锁定图纸
bidbench export current                                      # 导出只含现行版的图纸文件夹
bidbench export mirror                                       # 导出给 agent 读的数据镜像
bidbench serve                                               # 本地工作台
bidbench build --as-of 2                                     # 还原到第 2 批时的状态
bidbench log                                                 # 操作日志：什么时候收了什么、做过哪些决定
```

人工决定可以在工作台里点按钮完成，也可以用命令：

| 决定 | 命令 |
| --- | --- |
| 同版次内容不同，采用其中一份 | `bidbench decide sheet_pick "电施-01\|B" <page_id>` |
| 指定现行版次 | `bidbench decide sheet_current 结施-04 C` |
| 整套重发中消失的图：已作废 / 仍有效 | `bidbench decide sheet_void 建施-05 voided`（或 `keep`） |
| 缺图：列入答疑 / 不需要 | `bidbench decide missing 建施-09 ask`（或 `not_needed`） |
| 目录版次不符：列入答疑 / 以收到的为准 | `bidbench decide catalog_rev "建施-06\|B" ask`（或 `ignore`），键见问题中心的按钮 |
| 风险文件：安全 / 有风险 | `bidbench decide risk <文件编号> safe`（或 `dangerous`），编号见收图输出或问题中心 |
| 确认事实的值 | `bidbench decide fact 地上层数 "20 层" --note "结施-01 计入了机房层"` |
| 撤回一个决定（问题回到“待处理”，可以重新选） | `bidbench revoke missing 建施-09`（种类和键与 decide 相同） |

## 指引：不知道下一步做什么

工作台右栏“问题中心”最上面是 **下一步**：按“收图 → 认写法 → 看图识别 → 处理问题 → 导出”看项目到了哪一步，
只写眼下最该做的一件事和为什么做，旁边的按钮直接去做（收图、去识别、跳到要处理的问题并展开说明……）；
后面还有哪些事也列着，点名字就去做。做完一步自动换下一步。暂时不想做的点“先做别的”，这一步先放着
（只记在本机；牵涉的问题有变化时会再提醒），点“放回来”恢复。风险文件、收第一批图不能跳过。
前面的步骤做完了，后面的才打勾：没识别完，“处理问题”就不算完。

每个问题下面有 **怎么选？**：这是什么问题、去哪看、拿不准时选哪个、选了以后会怎样（没有选项的问题是“这是什么？”）。
说明统一写在 `bidbench/guide.py`，工作台里的 AI 助手解释问题、说下一步时用的也是这一份。

点过的选择都在 **做过的决定** 里，写成人话（带文件名）。选错了点“撤回”：问题回到“待处理”，再选一次。
撤回也记在操作日志里。

## 一级识别：先看名字

收完图马上就有全貌，不用等看图识别。每个文件只看文件名、所在文件夹和 PDF 自带的文字，推出：

- **图号**：按 ISO 19650 的常见写法认（项目-发起方-分区-楼层-类型-角色-编号，如 `PRJ1-ARC-ZZ-00-DR-A-1001`），
  也认 `建施-01`、`A-101`；文件名里的图号在 PDF 文字里也找得到，把握就是“高”。ISO 编号的前导零照原样保留。
- **图名、版次、状态码**：`_S4_P01_Ground Floor GA Plan`、`[P01]`、`Rev C02`、`B版` 都认；B2、A1 这类楼层号、轴号不会被当成版次。
  ISO 版次按 P01 < P02 < C01 < C02 排（P 初步、T 招标、C 合同施工）。
- **专业**：图号里的角色代码（A 建筑、S 结构、M/H 暖通、E 电气、P/D 给排水、L 景观、I 室内、C 总图），
  再看发起方代码（ARC、STR、MEP）和文件夹名（Architecture、Structure、Mechanical……）。
- **楼层**：Ground Floor、Level 05、Basement 01、Roof，以及图号里的楼层代码（00、05、B1、RF）。
  项目里有 Ground Floor 或 Level 00 时按英式数：Level 00 是 1F，Level 01 是 2F；没有的话 Level 01 就是 1F。
- **可能的内容**：看图名推测图里大概有什么（“6F 建筑平面图：可能有房间布置、轴网、门窗、尺寸”）；智能分类过的用 AI 的推测。
- **层数**：图上还没读到地上、地下层数时，按图名里最高、最低的楼层推测。

每一项都标来源和把握（高、中、低）。把握低的也先列出来——有总比没有好：看不出图号的文件用“文件：文件名”代替图号，
合订本文件名里列出的图号（`建施-07~08、10 详图`）拆成一张张，没读出图签的 CAD 文件按图号并到同名的 PDF 上。
图谱里这些图画虚线框（把握低的是点线、图名斜体），图纸卡片上逐项写推测和把握。

这些推测只当暂定：不拿来判断缺图、版本冲突，不导出到现行图纸文件夹。**二级识别按需做**：图纸卡片上“看图识别这张”，
框标题旁“看图识别 N 张”，搜索框旁“看图识别搜到的”，问题中心“看图识别把握低的”。看图识别后以图签为准；
文件名和图签对不上（文件名写 P01、图签是 P02）时列成问题，可以列入答疑或以图签为准。
已识别的图又收到同图号的新文件、文件名版次更新时，卡片上提醒“还没看图识别”，问题中心也有一条。

不论看没看图识别，图纸卡片上每一项（图号、图名、版次、出图日期、专业、楼层、内容）都写来源和把握：
看图识别的按识别给的分数换算（0.85 及以上高，0.6 以下低），AI 推测的一律算低，人工定的现行版标“已确认”。
图纸记哪些信息、每样从哪来、把握怎么标、哪些判断能用哪一层，见 [docs/图纸字段.md](docs/图纸字段.md)。

## 读 DWG

收图时用 LibreDWG（开源，随安装包附带）在本机读 DWG 的图签和文字，图纸不出电脑；DXF 软件自己读。规则见
`docs/图纸字段.md` 9.6：

- **一个图签算一张图**：模型空间里排了几张图的，每个图签块一张；按布局出图的，每个布局一张，图号从图签块、
  图签文字（“Sheet No.”旁边的字）或布局名认。
- 图签块属性里读出图号的，和看过图的 PDF 一样参与缺图、现行版判断（来源“DWG 图签”）。
- 图上的“详见建施-12”“REFER TO A-310”、详图索引符号里的图号算引用；DWG 转出的 PDF 常常只有图签文字，引用从 DWG 里补。
- 同图号同版次的 DWG 和 PDF 配成一份（看图、导出用 PDF）；DWG 版次更高时 DWG 是现行版，导出 DWG 原文件。
- 读不出（损坏、版本太新、超时）的按文件名暂定，问题中心有一条“DWG 读不出”。

以前收的 DWG 没读过的，问题中心“下一步”会有“读 DWG”；命令行 `bidbench read-dwg`，规则更新后 `bidbench read-dwg --again` 全部重读。
LibreDWG 是 GPLv3 的单独程序，安装目录 `_internal\libredwg` 里附许可证和源代码地址；不用安装包的，自己装 LibreDWG
（`dwgread` 在 PATH 里，或用环境变量 `BIDBENCH_DWGREAD` 指定）。

## 多栋塔楼

一个项目有几栋楼（T1、T2，或 1#楼、2#楼）时，每栋楼的图各算各的：同一个图号在两栋楼里是两张图，图谱、问题中心里写成
“T1 · 建施-01”，图谱按“塔楼 + 专业”分框。

- 塔楼从这些地方认：ISO 图号的分区代码；文件夹名（T1、Tower 1、1#楼、A座、裙楼、地下室、公共）；文件名和图名里的
  “1#楼”“Tower 1”；PDF 文字里的“子项名称”。图纸卡片上写着是哪栋、从哪认出来的、把握多大。
- 版本、缺图（目录、引用、编号断号）、楼层覆盖、同层图纸都在同一栋楼里算；引用公共的图（总平面、总说明）照样找得到。
- 同一个图号几栋楼都有、又看不出这份文件是哪栋的，问题中心会问你；T1 和 1#楼 这种不同叫法是不是同一栋，也问你一次。
- 只有一栋楼的项目不受影响，图纸身份还是图号。加塔楼以前做的决定（以哪版为现行、采用哪份文件等）原样有效。
- 从图上读出的层数、高度这些事实还是全项目一份，多栋楼层数不同时会报冲突。

## 现行版怎么定

- 版次高的是现行：P01 < P02 < C01，A < B，第1版 < 第2版。收图先后不算。
- 版次一样（或都没写）、内容却不一样：日期晚的是现行。日期先看修改记录里这一版那一行，没有修改记录才看图签日期；
  修改记录没跟着改时再比图签日期。版次一样的，问题中心提醒“改了图没升版”，可以列入答疑。
- 拿不准的列成问题让你选：版次高的日期反而早；版次写法不同（B 和 P02）或没写、日期也比不出；同版次几份内容不同、日期也一样。
- 后收到的反而是旧版：仍以版次高的为现行，问题中心提醒你核实（可能是新版作废、退回旧版）。
- 你在问题中心选过的（以哪版为现行、采用哪份文件），一律按你选的。

## 楼层：原叫法和换算

- 每张图的楼层记两样：图上或文件名里的原叫法（Level 05、Ground Floor、五层、4F~20F），和换算出的第几层，
  图纸卡片上显示成“Level 05（6F）”。
- 英文的 Level 01 是 1F 还是 2F，要看项目怎么数：软件先猜（图纸里有 Ground Floor、Level 00 就按英式，Level 00 是首层），
  问题中心请你确认一次；多栋楼各栋猜得不一样时按栋问。确认之前，这类楼层的把握最多算中。
- 夹层（5F夹层、Level 05M）算在下面那一层；避难层、设备层、转换层不另加标签，原叫法里写着的照样显示。
- 同层图纸、楼层覆盖都按换算后的楼层算，多栋楼的只在同一栋里找。

## 图号格式：每个项目认一次

各项目的图号分段不一样：有的是 ISO 19650 英国附录的 项目-发起方-分区-楼层-类型-角色-编号，有的是
项目-单位-楼栋-专业-类型-楼层-流水号、后面再跟两位版次（`PRJ1-ORG-T1-ST-DWG-GF-1202-00`）。软件按文件名先认一遍：

- 有 10 个以上四段以上、又不是 ISO 英国附录写法的图号时，问题中心出现“图号格式”卡片：每一段是什么、各代码的意思、
  套得上多少个文件，看不懂的代码打“？”。
- 「让 AI 助手认」：AI 助手看文件名的汇总（每一段出现过的代码、例图名、文件夹概况），看不懂的代码先看例图名，
  再看目录页和例图的 PDF 文字，还不懂就列出要看图识别的几页（由你点开始），最后写成一条“图号格式”提议。
- 你确认（软件猜的也可以直接确认）之后：楼栋按图号里的楼栋段分，专业、楼层、图类按码表认，
  末尾的版次段拿掉——`…-1007` 和 `…-1007-00` 算同一张图，图号的前导零照原样保留；以前做的决定照样有效。
- 确认之前，格式只用来分组显示（认不出专业的图、看不出楼层的图），楼栋、图纸身份、缺图、版本都不动。
- 选“先不用”就照旧按 ISO 英国附录的顺序读。以后收到套不上的图号，问题中心提醒，可以让 AI 助手补充。
- 专业多了三类：消防、智能化（通信网络、安防、音视频、楼宇自控）、岩土。

## 图纸识别

有两种识别方式，工作台「识别」里可以选，也可以选模型（会记住上次的选择）：

**按优先级识别**：估算时（不生成任务包、不渲染图片，几千页也只要几秒）按文件名、文件夹名把要识别的页面分成几档，
依次是 图纸目录清单 → 设计说明 → 平面（含布置、配筋）→ 立面剖面 → 其他图纸 → 详图大样表格，列出每档的页数、用时和例子。
勾选先识别哪几档，开始识别时才为这几档准备页面图片，并按这个顺序识别；剩下的以后再估算一次接着识别。
AI 助手的 `estimate_recognition` 也给出这个顺序，可以直接问它“识别优先级怎么排”。

**边识别边看**：识别途中每识别完约 20 页（或每分钟）就导入一次，左边的图谱、问题中心跟着更新，
可以先点开已识别的图纸；顶部常驻进度条，右栏去看别的也能看到进度。中途停下（额度用完、出错、关掉窗口），
已识别的页都已导入，接着识别时只识别剩下的。还有页面没识别时，问题中心会提醒缺图等结论要等识别完才准；
被引用或目录列出、但就在还没识别的页面文件名里的图号，先不算缺图。

**边识别边分类**：用 Codex 或 Claude 识别时，途中每导入约 200 页就在后台做一次[智能分类](#智能分类)，识别完再分一次，
英文图名、按图号认不出专业的图不用等全部识别完才归好类。

| 识别方式 | 费用 | 需要 |
| --- | --- | --- |
| Codex | 不另外花钱，占用 ChatGPT 账号的 Codex 用量额度 | 本机装好 Codex 命令行并用 ChatGPT 账号登录 |
| Claude API | 按用量付费，先估算花费 | Anthropic API 密钥 |

### 用 Codex 识别

```bash
npm install -g @openai/codex@latest    # 装好或更新 Codex 命令行（gpt-6.1-sol 需要 0.162 以上）
codex login                            # 用 ChatGPT 账号登录
bidbench recognize --executor codex --dry-run               # 只生成任务包并估算用时
bidbench recognize --executor codex                         # 经济档：gpt-6.1-sol，中等思考
bidbench recognize --executor codex --tier strong --scope conflict   # 强档：加局部切片，深入思考
bidbench recognize --executor codex --model gpt-6-astra     # 换模型（能用的模型见 codex debug models）
```

- 每页调用一次 `codex exec`，一页约半分钟到一分钟，默认同时识别 3 页。识别要求、格式校验、失败重试、续跑、逐页记录都和 Claude 一样。
- 安全：Codex 在只读沙箱里运行，不读你自己的 Codex 设置（不带上全权限、插件和 MCP），不保存会话记录，
  工作目录是只放了这一页图片的临时文件夹。PATH 里的 Codex 和 Codex 桌面版自带的命令行，自动用版本新的那个。
- 模型不能用、没登录、额度用完时就停下，并说明怎么办；已识别的页先导入，任务包保留，之后用 `--task` 续跑。
- 图纸页面会通过 Codex 发送给 OpenAI 识别。图纸涉密时，先确认这符合项目的保密要求。

### 用 Claude API 识别

先配置 Claude API 凭据（任选其一）：

```bash
export ANTHROPIC_API_KEY=sk-ant-...      # 或者：ant auth login
pip install -e ".[claude]"
```

推荐的分级用法：先用经济档全量识别，再用强档复核有问题的页面。

```bash
bidbench recognize --executor claude --dry-run              # 只生成任务包并估算花费
bidbench recognize --executor claude                        # 经济档：claude-haiku-5-5，识别新页面
bidbench build
bidbench recognize --executor claude --tier strong --scope conflict   # 强档复核冲突页面
bidbench recognize --executor claude --tier strong --scope weak       # 强档复核识别不完整的页面
```

| 档位 | 模型 | 送给模型的内容 | 适合 |
| --- | --- | --- | --- |
| economy（默认） | claude-haiku-5-5 | 整页缩略图、图签放大图、文字层 | 首次全量识别 |
| strong | claude-opus-5-5 | 再加 3×3 局部切片，effort 为 high | 冲突页、低置信页、重点图纸 |

| 范围 `--scope` | 挑选的页面 |
| --- | --- |
| new（默认） | 尚未识别的页面，以及只有模拟执行器结果的页面 |
| weak | 识别不完整：模拟结果、字迹不清或图签缺失等问题、缺图号、图签把握低于 0.6（“没写单位”之类的备注不算，显示在图纸卡片的“识别备注”里） |
| conflict | 涉及版本冲突、改图未升版、后收到旧版或事实冲突的页面 |
| unrecognized | 尚未识别的页面 |
| all | 全部页面 |

说明：

- 像素完全相同的页面只识别一次，结果自动复用；整套重发时没变的图不会重复花钱。
- 使用结构化输出约束格式，导入前再用完整 schema 校验；没通过就带着错误重试一次。若 API 不接受这份 schema，会自动改为在提示里附格式说明，结果照样校验。
- 强档模型启用了服务端拒答回退（`fallbacks: "default"`），被安全分类器拒绝时由服务端换模型重跑。
- 系统提示开启了提示缓存。每次运行在任务包的 `results/run_log.md` 和 `usage.json` 里记录用量和估算花费。
- 识别过程逐页显示（识别出的图号、用时、用量，失败的原因），同时追加到任务包的 `results/progress.log`。
- 中断后用 `--task <任务包>` 续跑，已完成的页面会跳过。凭据缺失、模型不可用时第一页就会停下。
- 图纸页面会发送到 Anthropic API 识别。图纸涉密时，先确认这符合项目的保密要求。

## 更新

安装版见 [docs/安装与更新.md](docs/安装与更新.md)。下面是用 git clone 安装的源码版。

工作台检测到 GitHub 上有新版本时，顶部会出现“有新版本”，点开能看到更新内容，点“更新并重启”即可；
页头的版本号也能打开这个面板。命令行：

```bash
bidbench update --check     # 只检查
bidbench update             # 更新（会先列出更新内容并确认）
bidbench update --rollback  # 回到上一次更新之前的版本
```

- 需要用 `git clone` 安装，跟随 `main` 分支（每个 PR 合并前都通过 CI）。沿用本机 git 的登录凭据。
- 只做快进更新：本地改过代码、不在 `main`、与远程分叉时停下，不覆盖、不自动合并。
- 依赖有变化时自动补装（保留你已装的可选功能，如 `claude`、`mcp`）；Windows 上在工作台退出后再装，避开被占用的 `bidbench.exe`。
- 项目数据不在代码目录里，更新不会碰到。数据库结构升级时会先备份为 `bidbench.sqlite.bak-v版本-时间`。
- 更新过程记录在代码目录的 `.git/bidbench_update.log`。

## AI 助手

### 在工作台里直接问（Codex）

工作台上方的「AI 助手」：用本机的 Codex（ChatGPT 订阅额度，不另外花钱）回答这个项目的问题，比如“还缺哪些图？”
“地上层数到底是多少？”“帮我起草答疑问题清单”。

- 它用的是下面 MCP 那一套工具：查询全部只读；**处理问题、确认事实、锁定基线、记笔记只会生成提议**，
  提议卡片就显示在回答下面，你点“确认”才生效（问题中心的“AI 助手提议”里也有）。
- 回答过程实时显示它查了什么；回答里的图号可以点，直接跳到图谱上那张图。可以连续追问，「新对话」重新开始。
- 每个问题约半分钟到一分钟，可以随时“停止”。模型可选，默认 gpt-6.1-sol，会记住上次的选择。
- 对话记录存在项目的 `logs/AI助手对话.jsonl`，关掉再打开还能接着看；每个问题也记进操作日志。
- 安全：Codex 在只读沙箱里运行，不读你自己的 Codex 设置，不保存会话记录，只能用 bidbench 的工具。
  问题和查到的图纸信息会通过 Codex 发送给 OpenAI，图纸涉密时先确认这符合项目的保密要求。
- **认图号格式**：问题中心“图号格式”卡片上点「让 AI 助手认」，它会提议一份图号格式（见上文“图号格式”）。
- **改进建议**：助手用着发现工作台本身的不足（缺工具、数据不对、不好用），可以提一条“改进建议”（也是提议，
  不带项目信息）。你确认后记进本机的改进建议清单，开发者按清单改代码、开 PR；助手自己碰不到代码和 GitHub。
  查看清单：`bidbench suggestions`。

### 接入其他 agent（MCP）

`bidbench -p 项目目录 mcp` 把项目作为 MCP 工具集提供给 Claude 桌面版、Claude Code、Codex 等 agent。
助手能查询图纸、事实、问题、楼层覆盖、批次差异，并起草答疑；**改动只能提议**，在工作台“AI 助手提议”
或用 `bidbench confirm <编号>` 确认后才生效。接入方法见 [docs/MCP.md](docs/MCP.md)。

## 压缩包支持

| 格式 | 怎么解 | 需要安装什么 |
| --- | --- | --- |
| zip（含 GBK 文件名、ZipCrypto 加密）、tar | Python 自带 | 不需要 |
| rar4 / rar5、7z（不加密） | 系统自带的 bsdtar | Windows 10 及以上、macOS 自带，不需要；Linux 装 `libarchive-tools` |
| 加密的 rar | unrar 或 7-Zip | 装 WinRAR 或 7-Zip（Windows 上按默认安装目录和注册表找，装在别的位置也找得到） |
| 加密的 7z（含连文件名都加密的） | py7zr 或 7-Zip | `pip install -e ".[archives]"`（约 20 MB，主要是加密库），或装 7-Zip |

默认安装不增加任何体积。按 bsdtar → unrar → 7-Zip 的顺序尝试，成功即停；任何工具失败都整体作废，不用解了一半的文件。
压缩包里的符号链接一律跳过；含符号链接的压缩包只用 bsdtar 解，防止被链接带到压缩包以外。
一个工具都没有时，解包报告会写明需要装什么。分卷压缩包（`.part1.rar`、`.z01`）目前仍需先手工合并。
中文 Windows 自带的 tar 解不了文件名里带 `Ø` 这类字符的 rar；这时会提示安装 7-Zip 或 WinRAR，装好后重新收图即可。

## 文件夹和多个文件

收图来源除了压缩包，也可以是一个文件夹（连子文件夹一起收），或同一次收到的几个文件（工作台里在对话框中一起选中）。

- 整个文件夹或这几个文件算一个批次；里面的压缩包照样逐层解开、去重、检查风险文件。
  文件夹里直接放的压缩包相当于外层包，压缩包里再套的才算内层。
- 每个文件按内容存进项目，另在 `archives/` 下留一份只读的文件清单，记下原来的位置和结构。
- 不收系统自动生成的文件：`Thumbs.db`、`desktop.ini`、`.DS_Store`、Office 打开文档时留下的 `~$` 临时锁文件。
  符号链接和目录联接不跟进去；项目自己的目录在里面时自动跳过。
- 同一个文件夹内容没变时拒收；设计院在同一个文件夹里改了图，再收一次算新批次，
  按“整套重发”判断，文件夹里不见了的图会问你是作废还是漏发。
- 读不出来的文件（正被其他程序占用、没有权限）登记为“读不出来”，提醒你关掉占用它的程序后重收。

## 文件安全检查

收图时自动检查每个文件，只看文件名和内容特征，**从不打开或运行文件**：

| 检查项 | 风险 |
| --- | --- |
| CAD 自动加载脚本：`acad.lsp`、`acaddoc.lsp`、`acad.fas`、`*.mnl`（含中望、浩辰同类文件） | 高：CAD 打开同目录图纸时自动运行，是 CAD 病毒最常见的传播方式 |
| LISP 脚本里有复制文件、写注册表、启动程序等操作 | 高 |
| 可执行文件、双扩展名（`图纸.pdf.exe`）、文件名含反向显示字符、扩展名和实际内容不符 | 高 |
| 文件名含反向显示字符，但内容和扩展名对得上的 DWG、PDF、图片（常见于外方系统导出的文件名） | 低：不能运行，只写进报告，不进问题中心 |
| Office 文件含 VBA 宏、会从外部地址加载模板 | 高 |
| PDF 含 JavaScript、启动外部程序、Flash | 高（Flash 为中） |
| 其他 CAD 插件（`.vlx` `.dvb` `.arx` 等）、启用宏的格式、AutoCAD 命令脚本 `.scr` | 中 |

- 有本机杀毒软件时一并扫描：Windows 上自动调用系统自带的 Windows Defender，其他系统用 ClamAV（需先 `freshclam` 下载病毒库）。
  只报告不删除；收图后被实时防护隔离的文件也会标出来。`bidbench receive --no-av` 跳过。
- 收图时被杀毒软件拦下的文件（读不出来，或解出后马上不见了）按高风险文件列进问题中心：
  它没有收进项目，如果是图纸，需要发图方重新发一份干净的。解出后再和压缩包的文件清单核对一遍，少了的不会静默漏掉。
- 发现的问题进入问题中心，由你决定“确认安全”或“确认有风险”（后者列入答疑，请发图方核实）。AI 助手不参与这类判断。
- “导出现行图纸”和工作台里打开的 PDF 会去掉脚本、自动动作和附件，图面不变。
- 老项目或规则更新后，运行 `bidbench scan` 按最新规则重查全部文件并做一次杀毒扫描，报告在 `reports/文件安全检查.md`。
- DWG 文件本身不能运行代码，风险在同目录的脚本和插件。建议在 CAD 里把 `SECURELOAD` 设为 1 或 2，只从受信任位置加载脚本。

## 图纸知识图谱

工作台左边的图谱有两种样式，在图谱上方切换：

- **分组方块**：按专业分区，每张图一个小方块，写按规则压缩的短名（“平面12”“梁12”“通风B2”“剖面1-1”“墙身3”“目录”）。
  方块按图号顺序排满一行再换行；图号按百位分段排得整齐时（1xx 平面、2xx 剖面），每段另起一行，
  但只在最多多出一行时这样排——四位流水号、按楼层代码排的英文图号常常一张一段，按段换行会排成细长条。有多个版本的图画成叠影。
  一个专业的图在 10 张以上、又不止一类时自动分小框：智能分类过的按 AI 给的小类，没分类的按图类（目录说明、平面图、配筋图、
  立面剖面、详图大样、系统图、表格、规格书、计算书、其他；英文图名的 Cover、Drawing register、Plan、Section、Elevation、
  Detail、Schedule 也认）。
  排法是“一层一层”的：方块一行排得下的小框、大框并排放；要排好几行的占满一层，同一层差不多高，不留大块空白。
  多栋楼的项目每栋一个区块，标题写楼栋和张数，点一下收起整栋，看别的楼更方便。楼栋、大框、小框点标题就能收起或展开；
  按住方块拖动排版，松手吸附到最近的格子，拖到别的图上两张互换，拖出自己的框会放回原处。收起和拖动都按项目记在本机，
  工具栏的“复原排版”一键恢复；搜索或点开收起的框里的图时，会自动展开它所在的框。
- **关系网**：像 Obsidian 的图谱，圆点是图纸，线是引用关系；同一类的图自然聚成一团，按图类（粗分的几类）或按专业着色。
  滚轮缩放，拖动空白处平移，拖动圆点调整位置，双击空白处看全图；放大后显示短名。

两种样式都是：鼠标指向图纸，放大一点并弹出图号、图名、版次、源文件名，有多个版本时列出各版的日期和批次；
点击打开图纸卡片；上方的搜索框按图号或图名找图，回车打开第一张。图纸超过 150 张时，分组方块只画选中或指向的那张图的连线。

## 智能分类

让 AI 给图纸分专业、分小框、起中文简称，给项目事实分多级目录，图谱和思维导图按它显示。
只把图号、图名、所在文件夹和事实的名称、示例数值发给 AI，不发图纸页面。

- **什么时候分**：收图后（用过 Codex、Claude 识别的，按名字先分一次）和用 Codex 或 Claude 识别时（边识别边分，识别完再分一次）自动分，
  只分新出现的图纸和事实；
  图谱、思维导图工具栏和问题中心都有“智能分类”按钮，可以手动分，对结果不满意时勾“全部重新分”。
  命令行：`bidbench classify [--executor codex|claude] [--all]`。
- **图纸**：按图号认不出专业的（ISO 19650 这类英文编号，原来都排在“其他”里）用 AI 给的专业；按图号认得出的不改。
  分组方块里的小框按 AI 给的小类分（中英文图混在一起也能归到同一类，比如“剖面图”里既有 A-A 剖面也有 1-1 剖面），
  方块上写 AI 起的中文简称（Level 02 GA Plan → 2层平面），还没看图识别的图另有 AI 看名字推测的“可能的内容”。
- **事实**：分到大类（工程概况、楼层、轴网、结构构件、材料、建筑、机电、执行规范、其他）和下面一两级小类；
  事实按“写法”分类（KL3 截面、KL12 截面是同一类），以后新识别出的同类事实直接套用，不用再问。
- **不影响判断**：台账、版本、缺图、冲突的判断规则不变；AI 的回答存在数据库里，和识别结果一样是原始记录，派生结果每次重新计算。
  还没分到的照旧按规则显示。

## 事实思维导图

大类 → 小类 → 事实，按需分级：一个分组的事实不超过 12 条时直接列出；多了才往下分小类（按智能分类，还没分类时按名称粗分，
比如 1F 层高、3F~20F 层高归成“层高”）；直接挂着的事实超过 30 条时，再按名称开头的编号（KL1、KL2……）分一级。
每一级都能点开、收起，展开了哪些按项目记在本机；收起的分组上写条数和冲突数。分组和它的第一项排在同一行，点开、收起时上面的都不动。
同一分组里按楼层、编号的数字顺序排（三层在十二层前面）。从问题中心、证据跳到一条事实时，自动展开它所在的各级分组；
在图谱里选中一张图再看思维导图，这张图上的事实所在的分组自动展开、高亮。

## 图纸卡片：建模时找图

点开一张图，右栏是它的卡片，建模要用的都在上面：

- **现行版原图**：一键打开；详图合订本里的图直接打开对应那一页。版本链里每个旧版也能打开。
- **变更单**：改过这张图的变更单可以直接打开原件，并列出它还改了哪些图。右栏首页也有全部变更单、答疑的清单。
- **引用关系**：这张图写了“详见”的图，和写了“详见”它的图。
- **同层图纸**：按楼层把各专业管同一层的图列在一起（屋顶平面 ↔ 屋面梁配筋图，二层梁 ↔ 二~四层平面），楼层完全一样的排前面；
  图上没写“详见”的另一个专业的对应图靠它找。对应的图有严重问题（比如目录写了新版、手上只有旧版）直接写在旁边。
- **通用图**：设计说明、没写楼层的柱平面布置图，建哪一层都要看。
- **来自此图的事实**：数值和全项目取值；“本层结构标高”“适用楼层”这类只对本图有效的值单独列出，不跟别的图比较，不会报冲突。
  出处图全都被变更单改过的数值，提示“可能已被变更单修改”，事实卡片上可以直接打开那张变更单。
- **识别备注**：识别时记下的小问题（图签没有专业栏、没写单位），收在最下面。

AI 助手查图纸（`get_sheet`）拿到的是同样的内容。

给建模的 AI 用的还有三个工具（`docs/MCP.md`）：

- **按任务找图**（`find_sheets_for_task`）：给楼层、专业、构件（“3F、结构、梁”），返回该看的现行图（主图、通用图、图上“详见”到的图），
  每张写明为什么找到它，加上没发来的图、改过它们的变更单和相关问题。
- **相关图纸往外走**（`related_sheets`）：从一张图出发，按关系种类（引用、跨专业引用、目录列出、变更单、同层、通用图）往外走一到三步，
  每张图写着是从哪张图、哪句话连过来的。
- **跳到图上的位置**（`locate`）：给页面编号和位置，告诉它是哪张图哪一版（旧版会提醒）、本机文件第几页，读出那块地方的文字和引用。

数据镜像（`bidbench export mirror`）里另有一份 `relations.json`：全部图纸和关系，给程序直接读；图纸卡片里也列出同层图纸、通用图和 CAD 文件。

建模找图演练：`python samples/make_model_sample.py <目录>` 生成 3 批合成图纸（4 层办公楼，含详图合订本、缺图、升版、变更单），文件里的 `TASKS` 是 5 个建模任务各自该找到的图和该注意的事；用 Codex 识别后，从每个任务的起点图出发，看卡片上能不能找到。
自动打分：`python samples/find_eval.py` 用模拟执行器建好演练项目，只通过 AI 助手的工具（和 MCP 同一套）给 5 个任务找图，按该看的图、相关的图、缺的图、变更单四样算找到了几成，并列出没找到的和多给的；`--project <目录>` 给已经用 Codex 识别过的演练项目打分。改了找图相关的工具或识别，看分数涨没涨（`tests/test_find_eval.py` 守着现在的分数不往下掉）。

## 楼层覆盖检查

按图名（“一层平面图”“三层梁配筋图”“地下一层平面图”“屋顶平面图”“3~20层平面图”）读出每张图覆盖的楼层；
图名没写楼层的标准层图，再从“适用楼层 4F~20F”这类说明里读。

| 图类 | 检查方式 |
| --- | --- |
| 建筑平面图 | 按事实层的地上层数、地下层数，加上屋顶，检查每一层都有图 |
| 结构梁、板配筋图，机电平面图 | 只检查已出现楼层之间有没有断档，结果写“已出现楼层之间不缺”，并列出楼里还有哪些层没查 |

缺层生成一条“楼层覆盖”问题，写明依据、已有哪些层和缺哪些层，可以列入答疑或确认不需要。
层数本身有冲突时会注明“确认后结果可能变化”；缺口变化后，之前的“不需要”不再适用，会重新提示。
标准层图没写适用楼层时，单独提示。“作废还是漏发”还没定的图只算暂定覆盖：结果里注明，确认作废后那几层会变成缺图。

## 流水线

```
收图（批次登记）→ 递归解包 → 三级去重 → 拆页与文字层 → 识别任务包 → 执行器 → 校验导入
   → 图纸台账与版本合并 → 批次性质判断 → 缺图检查 → 关系图谱 → 事实层 → 问题中心 / 报告 / 导出
```

| 环节 | 说明 | 代码 |
| --- | --- | --- |
| 收图与解包 | 压缩包、文件、文件夹或几个文件为一批；原件只读保存；zip / tar 原生支持，rar / 7z 调用系统解压工具；GBK 文件名修复；加密、损坏、分卷、缺工具、读不出来都登记为问题 | `bidbench/ingest.py`、`bidbench/extractors.py` |
| 文件安全 | 静态规则 + 本机杀毒软件；导出时去除 PDF 脚本 | `bidbench/risk.py`、`bidbench/antivirus.py` |
| 去重 | 文件级 SHA-256；页面级像素指纹（合订本中的一页能对上单独的 PDF）；内容级差值哈希 + 文字相似度 | `bidbench/pdfpages.py` |
| 识别 | 任务包 + `spec/schema.json` 约定输出；执行器可替换；导入前严格校验 | `bidbench/recognition.py`、`bidbench/executors/` |
| 智能分类 | AI 给图纸分专业、小类、起简称，给事实分多级目录；只发图号、图名、事实名称；结果存库，派生时套用 | `bidbench/classify.py` |
| 派生状态 | 台账、版本链、现行版、冲突、作废还是漏发、缺图、关系、事实层、基线 | `bidbench/state.py` |
| 报告与导出 | 解包报告、到图差异报告、图纸台账、缺图清单、答疑问题清单、项目事实；现行图纸文件夹；数据镜像 | `bidbench/reports.py`、`bidbench/export.py` |
| 工作台 | 图纸知识图谱（分组方块、关系网）、事实思维导图、问题中心，可回看任意批次；收图、识别、导出等操作在后台任务里跑 | `bidbench/server.py`、`bidbench/web/index.html`、`bidbench/ops.py` |
| 桌面版与安装包 | 独立窗口（WebView2）；PyInstaller + Inno Setup 打包；从发布仓库下载安装包更新 | `bidbench/desktop.py`、`bidbench/release.py`、`packaging/` |

**数据原则**：数据库只存原始登记（批次、文件、出处、页面、识别结果、智能分类）和人工决定。台账、事实等派生结果每次重新计算，
所以任意批次的状态都能还原，规则改进后旧项目也能直接受益。

## 项目目录

```
项目/
  bidbench.sqlite      原始登记 + 人工决定（识别结果、智能分类也在这里）
  archives/            收到的压缩包原件（只读）
  blobs/               解出的文件，按内容哈希存放
  recognition/tasks/   识别任务包
  reports/             报告（Markdown）
  exports/             现行图纸文件夹、mirror/ 数据镜像、state.json
  logs/                操作日志（按月一个文件）
```

项目目录含有图纸，不要提交到仓库（`.gitignore` 已排除常见位置）。

## 已知限制

- 模拟执行器只认文字层里“图号 / 图名 / 版次 …”这类标签写法，真实图纸需要多模态执行器。
- 图谱用合成的 957 张图项目测过；几千张以上时关系网的计算会变慢，分组方块不受影响。
- DWG 只读图签和文字，不读图形；天正等插件的自定义对象读不出；多人协作暂未实现。
