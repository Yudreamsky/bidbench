# 图纸识别任务说明 v0.2（任务包模式）

> 这份说明由 bidbench 生成识别任务包时自动放进任务包，交给 Codex 等 agent 的目标模式执行。
> 解包、去重、拆页、渲染、抽文字层已经由系统完成，你只负责**看图识别**。

## 目标

对本任务包 `manifest_in.json` 中列出的**每一页**，输出一个符合 `schema.json` 的结果文件。

**完成标准**（全部满足才算完成）：

1. 每一页在 `results/pages/` 下都有 `<page_id>.json` 和 `<page_id>.md`。
2. 每个 JSON 都通过 `schema.json` 校验（可用 Python `jsonschema` 库）。
3. `results/run_log.md` 记录遇到的问题；没有问题也写“无”。

## 任务包内容

| 路径 | 内容 |
| --- | --- |
| `manifest_in.json` | 待识别页面清单：`page_id`、`source`（直接照抄进结果）、图片和文字层的文件名 |
| `pages/<page_id>.png` | 整页图片，约 150 dpi |
| `pages/<page_id>-titleblock.png` | 右下角图签区域放大图，约 300 dpi；图签不在右下角时以整页为准 |
| `text/<page_id>.txt` | PDF 文字层全文；扫描件为空 |
| `text/<page_id>.json` | 文字层逐行文字和位置（`bbox` 已归一化到 0~1，原点左上角） |
| `schema.json` | 输出格式，必须完全遵守 |

**不得修改任务包里除 `results/` 以外的任何文件。**

## 识别要求

1. **页面类型** `page_kind`：图纸、图纸目录、设计说明、变更单、答疑或澄清、封面、其他。
2. **图签** `title_block`：图号、图名、专业、版次、出图日期、比例、项目名称、设计单位，以及修改记录栏的每一行。图号保持图上写法，只去掉多余空格。
3. **引用** `references`：详图索引符号（如 ⑤/建施-12）、文字引用（如“详见建施-17”“未注明者详见结施-01”）、图集引用。记录原文、指向的图号、类型和位置。
4. **图纸目录** `catalog_entries`：仅目录页填写，逐行提取图号、图名、版次，一行都不能漏。
5. **全页内容** `content`：
   - `summary`：一两句话说明这张图画的是什么
   - `notes`：设计说明、附注，按条目分开
   - `tables`：表格，保留表头和每一行
   - `key_values`：层数、层高、标高、建筑高度、面积、轴网、构件截面、墙厚、材料强度等级等，写名称、数值、单位、原文和位置；原文连同紧跟着的限定说明一起抄，例如“地上 21 层（含屋顶机房层）”。只对这张图有效的值（本层标高、适用楼层），名称照写“本层结构标高”“适用楼层”，不会拿去跟别的图比较
   - `standards`：引用的规范和标准，写编号和名称
6. **问题** `issues`：字迹不清、图签缺失、一页多图、文字层与图像不一致等。

## 来源与把握程度

- `source`：`text_layer`（来自文字层）、`vision`（来自看图）、`both`（两者一致）；`cad` 是软件读 DWG 时用的，看图识别不要用
- `confidence`：0.9 以上表示文字层清楚或两者一致；0.6~0.9 表示看图且图像清晰；0.6 以下表示不确定
- `bbox`：`[x0, y0, x1, y1]`，相对整页宽高，取值 0~1，原点左上角

## 硬性规则

1. **不编造。**看不清就填 `null`，并在 `issues` 里说明。
2. **文字层优先。**文字层与看图结果不一致时两个都记，并在 `issues` 注明。
3. **完全按 `schema.json` 输出**，不增减字段。
4. 每页的 `run` 写明执行器、模型名称、本说明版本号 `0.2`、完成时间。
5. 某页结果已存在且能通过校验就跳过，支持中断后续跑。

## 跑完之后

在项目目录运行：

    bidbench import <本任务包路径>/results
