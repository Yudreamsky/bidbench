# 图纸字段：由浅到深

这份文档写清楚 bidbench 记哪些图纸信息、每样从哪里来、把握怎么标、哪些判断能用它。
**加字段、改识别、改判断之前，先改这份文档。**

文中“现状”指写这份文档时（构建 b33）软件的做法；要改的部分按第 10 节的顺序做。

## 1. 三样东西：文件、页、图纸

| | 是什么 | 例子 |
|---|---|---|
| 文件 | 收进来的一个 PDF、DWG 或图片 | `建施-07~08 详图合订本.pdf` |
| 页 | 文件里的一页 | 合订本的第 2 页 |
| 图纸 | 一张图，由“塔楼 + 图号”认定 | T1 的建施-01 |

- 一个文件里可以有多张图纸（合订本）；一张图纸可以有多个文件（不同版次，或 PDF、DWG 各一份）。
- **图纸身份 = 塔楼 + 图号**。T1 的建施-01 和 T2 的建施-01 是两张图，各自排版本、各自查缺图。
  ISO 19650 图号的第三段（分区代码，如 `PRJ1-ARC-T1-05-DR-A-1001` 里的 T1）已经写明塔楼，这种图号本身就够。
- 显示：只有一栋楼的项目还是写图号；多栋楼的项目写成“T1 · 建施-01”。

## 2. 由浅到深的来源

| 层 | 从哪来 | 花费 | 把握 | 说明 |
|---|---|---|---|---|
| 0 | 文件本身 | 不花钱 | 确定 | 收图时就有 |
| ① | 文件名、所在文件夹 | 不花钱 | 低到中 | 收图后马上有（一级识别，`bidbench/names.py`） |
| ② | PDF 自带的文字、DWG 里的文字 | 不花钱 | 中 | 只有 CAD 直接导出的 PDF 有，扫描件没有；DWG 的文字见 9.7 |
| ③ | 看图签 | AI，按页收费 | 高 | 看图识别；图纸身份以图签为准 |
| ③ | DWG 图签块的属性 | 不花钱 | 高 | 收图时用 LibreDWG 在本机读（9.7），和看图识别读出的图签同样算数 |
| ④ | 看图面 | AI，比③贵 | 看内容 | 看图识别的内容部分 |
| 推出 | 跨图比对 | 不花钱 | — | 不存，每次重新算（`bidbench/state.py`） |
| 人定 | 你的决定 | — | 已确认 | 压过所有机器判断 |

①和②互相印证（文件名里的图号在 PDF 文字里也找得到）时，把握算高。

## 3. 每个字段都带同一套出处

| 项 | 说明 |
|---|---|
| 值 | 整理、换算后的值，如 `6F`、`2026-03-01` |
| 原文 | 图上或文件名里的原样写法，如 `Level 05`；和值不同时才写 |
| 来源 | 文件名、文件夹、PDF 文字、看图识别、AI 推测、人工 |
| 把握 | 高、中、低、已确认 |
| 出处 | 哪个文件第几页 |

以前是三套写法，现在统一成上面这一套。工作台的图纸卡片、AI 助手查图纸（`get_sheet`）都按这一套给：

| 地方 | 以前 | 现在 |
|---|---|---|
| 看图识别（`bidbench/spec/schema.json`） | 每项 0–1 的分数；来源分文字层、图像、两者 | 分数换成高中低：0.85 及以上为高，0.6 以下为低（和“图签把握低”是同一条线），中间为中；来源写“看图识别”，注明是 PDF 文字层还是图像。识别结果本身照原样存，只在显示和判断时换算 |
| 一级识别（`names.py`） | 高、中、低，带来源 | 不变，补上出处 |
| 事实（`state.py`） | 两张以上图说法一致为高，只来自 PDF 文字为中，只来自一张图的看图结果为低；另有人工确认、冲突 | 不变 |
| 智能分类（`classify.py`） | 不标 | AI 推测（专业、可能的内容、小类）一律算低 |
| 人工决定 | — | 人工定的现行版标“已确认” |

按规则推出来的项，把握跟着它的依据走：

- 楼层从图名推的，跟图名的把握；英文的 Level 几是第几层要看全项目怎么数，最多算中。
- 专业按图号认：ISO 角色代码、中文前缀（建施、结施）算高，只凭英文首字母（A-101）算中——第一段只有一个字母才算，
  ATB-3008 这种第一段是项目代码的不按首字母认；按图号认不出的看文件夹（Structure、Struktur、结构……），算中。

| 类别 | 要记的 | 用来 |

## 8. 推出来的结论

现行版、旧版、作废、缺图、版本冲突、目录和实际对不上、文件名和图签对不上、同层图纸、通用图、
受哪张变更单影响、被哪些图引用、事实冲突。这些都不存，每次重新算。

哪些结论能用哪一层：

| 结论 | 能用 | 不能用 |
|---|---|---|
| 现行版、缺图、作废、版本冲突 | ③图签（看图识别或 DWG 图签属性）、目录、变更单、人工 | ①②只能提醒，不能下结论 |
| 找图、分组、图谱、思维导图 | 任何一层，标出把握 | |
| 导出现行图纸 | ③识别过或人工确认过的图（现行版只有 DWG 的，导出 DWG 原文件） | 只按名字暂定的图不导出 |
| 事实冲突 | ④读出的数值 | 按图名推测的数值不报冲突 |

拿不准的判断（版本、作废、冲突、塔楼归属）不自动拍板，列成问题并给出选项。

## 9. 规则

### 9.1 塔楼

1. 取值：项目里实际有的各栋（T1、T2……）；裙楼、地下室各算一栋；全项目通用的图（总图、总说明）归“公共”。
2. 同一栋楼的几种叫法（Tower 1、T1、1#楼）并成一个：软件先列出候选，你确认一次。
3. 看不出是哪栋时：
   - 同一个图号只在一处出现：放进“未分塔楼”，把握低。
   - 同一个图号在几栋楼都有，又分不清这份文件是哪栋的：列成问题让你指定。
4. 以前按图号做过的决定（以哪版为现行、采用哪份文件等），加上塔楼后要原样带过去。

怎么认，从可靠到不可靠：人工指定 > ISO 图号的分区代码（ZZ、XX 不算）> 文件夹名（T1、Tower 1、塔楼1、1#楼、A座、裙楼、
地下室、公共）> 文件名和图名里写明的“1#楼”“Tower 1”“A座” > PDF 文字里的“子项名称”。文件名、图名里不认单独的 T1
（也可能是版次），也不认“裙楼”“地下室”（图名里多半说的是楼层，如“地下室顶板平面图”）。同一个文件放在几栋楼的文件夹里，
算“公共”。Tower 1、T01、塔楼1 自动并成 T1，1号楼并成 1#楼；T1 和 1#楼 这种不同写法是不是同一栋，问人。

按楼各算各的：版本链；缺图（目录列出的、引用的、编号断号）；目录版次核对；楼层覆盖（每栋按自己图纸里出现的最高楼层查，
裙楼、地下室、公共只查断档）；同层图纸。引用公共的图照样找得到；只有别的楼才有的图，算这栋楼缺。

还是全项目一份的：从图上读出的事实（层数、高度……）。多栋楼层数不同时会报事实冲突，以后再分楼。

### 9.2 现行版：先比版次，版次一样再比日期

1. 版次高的是现行。版次按各自的写法排：P01 < P02 < C01（P 初步、T 招标、C 合同施工），A < B，第1版 < 第2版。
2. 版次一样（或都没写）、内容却不一样时，日期晚的是现行：
   - 版次一样的，问题中心照样提醒“改了图没升版”，投标时可能要提答疑；
   - 日期也一样或没有日期，列成问题让你选。
3. 版次和日期打架（版次高的日期反而早）：列成问题。
4. 同一张图混着两种版次写法（既有 B 版又有 P02）：版次没法比，按日期；没有日期就问你。
5. 日期优先用修改记录里这一版那一行的日期，没有修改记录才用图签上的出图日期
   （不少图签上写的是第一次出图的日期，升版后不改）。
6. 收图批次先后不参与定现行版。后收到的反而是旧版时，默认版次高的为现行，问题中心提醒你核实（可能是新版作废、退回旧版）。

补充：同一版次几份内容不同、修改记录又没跟着改（几份的修改记录日期一样）时，再比图签日期。
人工定过以哪版为现行的，不再提这几类问题；人工选过采用哪份文件的，按选的。

问题中心里：拿不准的（版次和日期对不上、版次写法不同或没写又比不出日期、同版次同日期内容不同）是“版本冲突”，算严重问题；
“改图未升版”“后收到的反而是旧版”是提醒，现行版已经按规则定了。

### 9.3 楼层：保留原叫法，再换算

1. 每张图记两样：原叫法（Level 05、L30、五层、Ground Floor）和换算出的第几层，显示成“Level 05（6F）”。
2. 按塔楼分别换算。“同层图纸”只找同一栋的同一层；地下室这种几栋共用的楼层，和每一栋的同层都算同层。
3. 换算规则（Level 00 是不是首层，Level 01 是 1F 还是 2F）软件先猜、写明理由，每个项目让你确认一次；各栋叫法不同时按栋确认。
4. 夹层、避难层、设备层、转换层、屋面不另加标签：原叫法里写着的照样显示；换算时夹层排在上下两层之间。

补充：没有 Level 01、1st Floor 这类写法（也没有图号里 01、02 这样的楼层代码）的项目不问。确认之前，这类楼层的把握最多算中；
确认之后跟着图名的把握。问题中心里是“楼层数法”，选项里软件猜的那个排在前面。

### 9.4 投标特有的字段

先加两个，以后想到再补：

- 工作包、标段：从文件夹名、图号、图签里读。
- 出图状态：招标用、仅供参考、施工用（ISO 的 S2 仅供参考、S4 阶段审批这类）。

### 9.5 图号格式：每个项目认一次，你确认后才用

图号怎么分段，各项目不一样。ISO 19650 英国附录的顺序是 项目-发起方-分区-楼层-类型-角色-编号（`PRJ1-ARC-T1-05-DR-A-1001`）；
也有 项目-单位-楼栋-专业-类型-楼层-流水号、后面再跟两位版次的（`PRJ1-ORG-T1-ST-DWG-GF-1202-00`）。按固定顺序去读，
专业、楼层、楼栋会读错或读不出，带不带版次后缀的同一张图会算成两张。所以每个项目先认出自己的图号格式：

1. 软件汇总：文件名里四段以上的图号按段数分组，每一段出现过哪些值、各多少个文件，每个值附例图名和页面编号；
   再加上文件夹目录的概况。只用文件名和文件夹名。
2. 软件先猜一个格式：看每一段的取值像什么（ST、AR 像专业，GF、01、XX 像楼层，DWG、DET 像类型，只有一个值的是项目代码，
   流水号后面再跟的两位数字是版次）。把握低。
3. AI 助手（Codex）读汇总，说出每一段是什么、每个代码什么意思、项目里有几种格式，写成一条“图号格式”提议。
   看不懂的代码按这个顺序找答案：例图名 → 目录页和这个代码的一两张图的 PDF 文字（只发文字）→ 列出要看图识别的几页，
   由你点开始（会把这几页发给 OpenAI）→ 都找不到，写成拿不准的问题。每个代码的意思写明是从哪看出来的。
4. 软件拿格式套一遍所有图号：套得上多少个文件、哪些套不上、哪些代码没有说明，附在提议上。
5. 你确认（问题中心的“图号格式”，或“AI 助手提议”），也可以选“先不用”。确认的格式记成人工决定。

问题中心的“图号格式”只在有 10 个以上四段以上的图号、又不是 ISO 英国附录写法时出现。

确认之前，格式只用来分组显示：按图号认不出专业（“其他”）的图用格式里的专业（把握低），图名里看不出楼层的用图号里的楼层代码，
小框按类型代码分。楼栋、图纸身份、缺图、版本都不受影响。

确认之后：

- 楼栋按图号里的楼栋段（人工指定的除外），码表里写“公共”的归公共。这种图号本身带着楼栋，图纸身份仍只写图号，不加“T1 · ”。
- 末尾的版次段从图号里拿掉，记成这份文件的版次（来源“文件名”）：`…-1007` 和 `…-1007-00` 是同一张图。
- 图号各段照原样，前导零保留（`0002` 不再变成 `02`）。以前按旧写法做的决定原样带过来。
- 专业按专业段的码表，把握高。专业多了三类：消防、智能化（通信网络、安防、音视频、楼宇自控）、岩土。
- 楼层按楼层段的码表换算：XX 不分层，GF 首层，01 这类按 9.3 的数法，LR、UR 这类按码表写的（写成屋面就算屋面）。
- 类型段按码表分图类：DET 详图大样、SCH 表格、SPEC 规格书、CAL 计算书。
- 以后收到的图号套不上（新的段数、新的代码），问题中心提醒，可以让 AI 助手补充，补完再确认一次。

没有确认格式（或选了“先不用”）的项目照旧按 ISO 19650 英国附录的顺序读。

### 9.6 图纸之间的关联

给 AI 建模找图用：从一张图出发，知道还要看哪些图、看那张图的哪一块。关联都从④看图识别来（目录列出从目录来），
每条带原文、出处页面和位置，不存库，每次重新算。

| 种类 | 图上长什么样 | 编号 | 指向 |
|---|---|---|---|
| 详图索引 | 圆圈中间一道横线，上面详图编号、下面详图所在图号；或写成 ⑤/建施-12 | 详图编号（5） | 那张图上编号相同的详图（有就带位置） |
| 剖切 | 剖切符号两端的编号，旁边注明剖面在哪张图（1-1 剖面见建施-05；英文图是 301/1，图号在前） | 剖面编号（1-1） | 那张图上同名的剖面 |
| 立面 | 立面索引符号（英文图 201/1 指 A-201 的第 1 个立面） | 立面编号 | 那张图上同编号的立面 |
| 文字引用 | “详见建施-08”“未注明者详见结施-01”“大样见建施-09”“REFER TO A-301” | 没有 | 整张图；只写了单位没写图号的（REFER TO 某院 DRAWINGS）不连线，原文留在识别结果里 |
| 变更涉及 | 变更单、答疑条文里写到的图号（“结施-03 二层梁配筋图：……”“建施-07 ② 女儿墙大样：……”） | 写到详图编号就带上 | 被改的图；这张图状态变成“有变更单” |
| 目录列出 | 图纸目录的一行 | 没有 | 只在缺图时作为关联 |
| 共用参照 | DWG 里绑定的外部参照名一样（同一个核心筒、同一套柱子被几层的平面共用） | 参照名 | 用了同一个参照的图，不分方向 |
| 同层、通用图 | 不画在图上，按楼层、图类推出来 | 没有 | 整张图 |

- 指向别的专业的图叫跨专业，种类不变。
- 剖面图上的楼层标高表（Level 05 - 18.00 m）记成关键数值，给楼层换算当证据，不算关联。
- 引用带编号、被指的图上又读出了同编号的详图（或同名剖面）时，关联带上那块详图的位置，找图工具可以直接跳过去；
  编号对不上的照样保留关联，只是不带位置。
- 分区、轴线范围：一层平面拆成几张图（A 区、B 区，或 1~12 轴、12~24 轴）时，同层的图按分区和轴线范围区分，
  建某一块时先看管那一块的图。读不到时为空，不猜。

### 9.7 DWG：用 LibreDWG 在本机读

DWG 不能看图识别（AI 只看图片），以前只按文件名暂定。现在收图时用 LibreDWG（开源，随安装包附带，单独的程序，
软件只是调用它）在本机读出 DWG 里的内容，图纸不出电脑。DXF 不用 LibreDWG，软件自己读。
读的规则（`dwg.INSTRUCTION_VERSION`）改了以后，按旧规则读过的文件算没读：下一步提示“读 DWG”，收图后也会自动重读，不用手动 `--again`。

1. **一个图签算一张图**：
   - 图签块（带属性的块参照）里有图号的，每个一张图。国内常见一个 DWG 的模型空间里排好几张图，每张一个图签；
     图签外框里的文字归这张图（外框按图签块里的线算；算不出就归最近的图签）。
   - 布局里没有这种图签块的，每个有内容的布局一张图（按布局出图，常见于 Revit 导出和外方设计院）。
     模型空间里的文字按各布局视口看到的范围归到那张图。
   - 模型空间里有图签块、布局里也有按视口出的图时（模型空间一张图，布局又看模型空间的另一块），
     各布局视口看得到的模型空间文字也算这张布局图的（同时还留在模型空间那张图上），不然布局图上只剩图签的字，
     `check_basis` 对不上轴号。
   - 只有模型空间、又没有图签块的，整个模型空间算一张图。别的布局都认出了图号时，没几个字、也没有视口的空布局不算。
2. **认图号、图名等**，从可靠到不可靠：
   - 图签块属性名认得出（图号、图纸编号、DWG_NO、DRAWING_NO、SHEET_NO、NO GAMBAR……；图名分几行写的“图名1、图名2”“JUDUL1、JUDUL2”连起来）：
     把握高，来源“DWG 图签”。版次、出图日期、比例、项目名称、设计单位同样按属性名认。
   - 属性名是各家自己编的（如 KD0105）：图签块里只有一个属性值像图号，就用它，把握中。
   - 图签拆成几个块的（印尼常见：ATT KOP 写图号 NOGBR、图名，STATUS KOP 写版次 REV、日期 TGL）：别的块里认得出的图签项
     补到同一张图上（在哪张图的图签外框里就归哪张，这个空间只有一张图的归它），已有的不覆盖。
   - 图签是普通文字（Revit 导出的图常这样）：“Sheet No.”“图号”右边或下面最近的字，把握中。
     版次只取像版次的值（A、C、P02、03、第2版……）：修改记录表头“REV | DESCRIPTION | DATE”右边是别的表头，取 REV 下面的那格。
     标签写在图框块的块定义里、值是布局上散放的文字时（Revit 导出的图框：块里只有“Sheet No.”“Sheet Name”“Revision”这些字，
     没有属性），把块里的字摆到图框插入的位置再配对；分两行写的标签（“Sheet”下一行“No.”）合成一个。
     值写在标签下面那一格的中间，所以按格子配：格子从标签到同一行右边下一个标签为止（“Scale”下面是“As indicated”，
     不是旁边“Drawn By”格子里的 Rn）；图名、比例、项目名称一格里分几行写的连起来。
     图号前面多出来的“-”（“-S-3036”，Revit 的图号前缀空着时）去掉。
   - 修改记录表：表头“REV | DATE | DESCRIPTION”同一行，各行的版次一格一格挨着排，往下或往上（Revit 的表头在下、行往上长，
     行还可能写死在图框块里）。离表头最远的一行是最新一版；图签里没认出版次的用它，各行记进修改记录（版次、日期、说明）。
   - 图上本来就没有版次的（没有修改记录、版次格空着），`check_basis` 里依据这张图、也没写版次的构件算对得上，不再一直“要复核”。
     构件的数值在识别内容里没找到时，再找这一页的文字（DWG 的文字全在里面）；350x850 和 350×850 算一样；
     图上分几处写、依据里连成一行的（板标注“T=140mm”“EL.+138.600”），每段都在就算对得上。
     依据原文以“推断”开头的（Revit MCP 翻模时没有标注、按附近推断的尺寸）图上本来没有，直接“要复核”，写明待确认。
   - 配位置时字高按至少 2 算（图框里的小字常只有 1 mm 上下，按它算格子、行距太窄）。
   - 布局名像图号（本地设计院常把布局名写成图号，如布局“A-224”）：用布局名，把握中。
   读出图号的图和看图识别读出的图签一样参与现行版、缺图、版本冲突；文件名里的图号和图签不一样时（A-224 和 LDI-A-224），以图签为准。
   文件名和图签只是前缀不同、后面的编号一样的（文件名用项目代号 PRJ-3036，图签是 S-3036）不算“文件名不符”；
   `check_basis`、`sheet_detail` 查文件名里的那个图号（以前按文件名暂定时记下的依据）也能找到这张图（只有一张图对得上时）。
3. **DWG 里的文字**：单行文字、多行文字、不是图签的块属性（详图索引符号的编号、所在图号）。用来：
   找文件名里没有的图号（同 PDF 文字，②层，中）；找引用（“详见建施-12”、索引符号里写的图号），把握中，来源“DWG 文字”。
   “A-101”这种短图号只在紧跟“详见”“REFER TO”之类的词、或在索引符号里才算（不然门窗编号、构件编号也像图号）；
   索引符号里另一个短编号（⑤/建施-12 的 5）记成详图编号，关联能跳到那块详图。
   “201/1”这种只写了图号尾数的剖切、立面索引先不从 DWG 认。
   块里套的带属性的块（动态块里的轴号圈 AS、索引符号）也读，属性摆到用它的地方，当图上的字；它们不当图签。
   `check_basis` 核对轴号这种很短的值（3 个字以内）时，要这一页有单独一行就是它才算对得上（“1:100”里的 1 不算）。
   **外部参照**：附着的（块记录里有参照文件路径）和绑定进来的（里面的块改名成“参照名$0$原名”）都记下参照名，
   归到用它的那张图（同一空间几张图的按范围重叠，布局按视口看到的范围），几张图用同一个参照就是 9.6 的“共用参照”。
   和 PDF 配成一份时，参照名同引用一样并过来。
   天正等插件的自定义对象（天正文字、天正索引符号）LibreDWG 读不出，要在天正里先转成普通 CAD 对象再发图。
4. **和 PDF 配对**：同一张图（塔楼 + 图号）、同一版次的 DWG 和 PDF 算同一份，不提醒“改图未升版”；看图、导出优先用 PDF。
   DWG 转出的 PDF 常常只有图签文字，图上的引用只在 DWG 里：配成一份时，DWG 读出的引用并到这一份上。
   版次不同的照 9.2 排现行版：DWG 的版次高就是 DWG 现行，拿不准的照样列成“版本冲突”让你选。
5. **读不出的**：文件坏了、版本太新、读超时（每个文件至少等 60 秒，大文件按大小多等，最多 15 分钟）、没装 LibreDWG，照旧按文件名暂定。
   读失败的在问题中心列一条“DWG 读不出”（提醒，没什么可选的）。以前收的 DWG 没读过的，问题中心的“下一步”里点“读 DWG”补读
   （命令行 `bidbench read-dwg`）。
6. 读出的内容按识别结果的格式存（执行器写 `dwg`，`source` 写 `cad`）。认属性名的规则改了以后，用 `bidbench read-dwg --again` 重读，
   不做旧结果的兼容。
7. **翻模时只取这张图那一块**（`cad_file`）：一个 DWG 里有几张图时，Revit MCP 读整个模型空间会把别的图也建进去，
   所以 `cad_file` 给出这张图在模型空间里的范围 `region`（一个或几个矩形 `[x0, y0, x1, y1]`，和 DXF 同一套坐标、同一个单位），
   交给 Revit MCP 的 `read_cad`、`cad_to_model`、`compare_cad_with_model` 只读范围里的东西：
   - 模型空间里排图框的：图签外框（图签块里的线算出的范围；图签转了 90° 之类算不出时不给，提醒翻模时自己框）。
     “图签块”只是图名旁边的小标签（归这张图的字铺开的范围比它大十倍以上，或块里没有线、只有属性）的，不当图框，不给范围并提醒；
   - 按布局出图的：这个布局各视口看到的模型空间范围，按视口的目标点和扭转角换算到模型空间；转了角度的取外接矩形。
     布局本身那个视口（看到的就是图纸本身）不算：AutoCAD 给它编号 1，但 dwg2dxf 转出的 DXF 里浮动视口也写成 1，
     所以先按“中心、高和布局一样”认，认不出再看编号，编号都一样的第一个是布局本身。
     布局里没有视口、图画在布局本身上的，Revit MCP 读不到，提醒在 CAD 里把内容移到模型空间或另存。
   - 整个文件只有这一张图、又框不出范围的，不给，读整个模型空间。
   范围是转出 DXF 后软件自己读 DXF 算的（同一个 DXF 只算一次，存在它旁边），不改识别结果的格式。
8. **dwg2dxf 写丢的块**：动态块（轴号、门窗常用）在 DWG 里引用的是匿名块（*U4、*U6），dwg2dxf 却把块参照写成光秃秃的“*U”，
   读 DXF 的软件找不到块，轴号、轴线整片丢掉。dwgread 读出的块名也是“*U”，靠不住，只用它给的“这个块参照用哪条块记录”（句柄），
   到 DXF 自己的块记录表（TABLES 里的 BLOCK_RECORD，按句柄）里找 dwg2dxf 写的名字补回；补的名字在 DXF 里有块定义才算补上。
   以前转好、存在 exports/dxf 里的 DXF，补法改了以后下次 `cad_file` 用到时再补一遍（旁边的 .blocks 记着按哪一版补过）。
   补不回的，`cad_file` 给 `dxf_warning`，请在 AutoCAD 里另存为 DXF。

### 9.8 分步识别：先搭地图，再一层层看图

几千页的项目，③④层（看图识别）按页花钱、花时间，不一口气全做，按用处分几步（`bidbench/recognition.py` 的 `STAGES`）：

| 步 | 做什么 | 来源 | 哪些页 |
|---|---|---|---|
| 1 地图 | 收图时自动做，不看图、不花钱 | ①②层，DWG 的③层（9.7） | 全部 |
| 2 重点图 | 看图识别，读全 | ③④ | 图纸目录、变更单答疑、清单和表（门窗表、Schedule、List、Register）、说明和规范书的头两页 |
| 3 建模主图 | 看图识别 | ③④ | 平面（含布置、配筋）、立面、剖面 |
| 4 按需深入 | 用到哪张识别哪张（按任务找图、图纸卡片里点） | ③④ | 详图大样、说明正文（第 3 页起）、认不出种类的页、同图号 DWG 已读出内容的 PDF |

每页归哪一步（`stage_group`）：

1. 先看地图带路：这一页①②层推出的图号，对得上已识别的目录条目、图签或 DWG 读出的图名，就按那个图名认种类；
   合订本里只认出图号的页，目录识别完以后就能归到平面、剖面。
2. 再看①层推出的图名，最后看文件名、文件夹（从里往外）。
3. 都认不出的归第 4 步；合订本开头两页的文字里写着“目录”的，归第 2 步。
4. 平面、立面、剖面的同图号已经有 DWG 读出的内容（9.7），PDF 这页归第 4 步。

种类只决定先后，不进台账、不参与缺图和版本的判断。识别过的页不再识别，所以每一步都能随时停、下次接着来；
估算时列出每步总共几页、已识别几页、还剩几页和要多久（`bidbench stages`、工作台「识别」、MCP `estimate_recognition`）。

### 9.9 信息深度：每张图现在知道到哪一层

每张图按它现行那一页的来源记一个信息深度（`state.DEPTHS`，`state.depth_of`），图谱方块左下角四格显示：

| 深度 | 叫法 | 怎么来的 |
|---|---|---|
| 1 | 地图 | 还没看图识别，只按文件名、文件夹、PDF 文字暂定（①②层） |
| 2 | 本机读出 | DWG 读出的图签和文字（9.7），或演示用的模拟执行器；没看过整张图 |
| 3 | 看图识别 | Codex、Claude 看过整张图（经济档） |
| 4 | 精读 | 强档：除了整张图还看了局部切片（识别结果 `run.tiles` 大于 0） |

缺图没有深度。DWG 和 PDF 配成一份的图按 PDF 那页算（看图、导出都用 PDF）。

**你可以指定**：右键方块选一个深度，记成人工决定 `depth`（键是图纸身份，值是 1~4；撤回照常）。

- 选的比现在深（3、4）：马上用上次的识别方式看图识别这张图的 PDF 页（4 用强档）；识别方式还没设好就在右栏选。
  分步识别时，这张图还没到指定深度的页排在第二步最前面（“你指定要看图识别的图”）。
- 选 1、2：分步识别时跳过这张图（估算里说明跳过了几页）；按任务找图、图纸卡片里照样能点“看图识别”。
- 已经到了的：只记下来，方块上不再有橙色框。

深度只说明信息从哪来，不改台账、缺图、版本的判断规则（那些仍按第 2 节各层的用法）。
