# 图纸字段：由浅到深

这份文档写清楚 bidbench 记哪些图纸信息、每样从哪里来、把握怎么标、哪些判断能用它。
**加字段、改识别、改判断之前，先改这份文档。**

文中“现状”指写这份文档时（构建 b33）软件的做法；要改的部分按第 10 节的顺序做。

## 1. 三样东西：文件、页、图纸

| | 是什么 | 例子 |
|---|---|---|
| 文件 | 收进来的一个 PDF、DWG 或图片 | `建施-07~08 详图合订本.pdf` |
| 页 | 文件里的一页 | 合订本的第 2 页 |
| 图纸 | 一张图，由“塔楼 + 图号”认定 | T1 的建施-01 |

- 一个文件里可以有多张图纸（合订本）；一张图纸可以有多个文件（不同版次，或 PDF、DWG 各一份）。
- **图纸身份 = 塔楼 + 图号**。T1 的建施-01 和 T2 的建施-01 是两张图，各自排版本、各自查缺图。
  ISO 19650 图号的第三段（分区代码，如 `PRJ1-ARC-T1-05-DR-A-1001` 里的 T1）已经写明塔楼，这种图号本身就够。
- 显示：只有一栋楼的项目还是写图号；多栋楼的项目写成“T1 · 建施-01”。

## 2. 由浅到深的来源

| 层 | 从哪来 | 花费 | 把握 | 说明 |
|---|---|---|---|---|
| 0 | 文件本身 | 不花钱 | 确定 | 收图时就有 |
| ① | 文件名、所在文件夹 | 不花钱 | 低到中 | 收图后马上有（一级识别，`bidbench/names.py`） |
| ② | PDF 自带的文字 | 不花钱 | 中 | 只有 CAD 直接导出的 PDF 有，扫描件没有 |
| ③ | 看图签 | AI，按页收费 | 高 | 看图识别；图纸身份以图签为准 |
| ④ | 看图面 | AI，比③贵 | 看内容 | 看图识别的内容部分 |
| 推出 | 跨图比对 | 不花钱 | — | 不存，每次重新算（`bidbench/state.py`） |
| 人定 | 你的决定 | — | 已确认 | 压过所有机器判断 |

①和②互相印证（文件名里的图号在 PDF 文字里也找得到）时，把握算高。

## 3. 每个字段都带同一套出处

| 项 | 说明 |
|---|---|
| 值 | 整理、换算后的值，如 `6F`、`2026-03-01` |
| 原文 | 图上或文件名里的原样写法，如 `Level 05`；和值不同时才写 |
| 来源 | 文件名、文件夹、PDF 文字、看图识别、AI 推测、人工 |
| 把握 | 高、中、低、已确认 |
| 出处 | 哪个文件第几页 |

以前是三套写法，现在统一成上面这一套。工作台的图纸卡片、AI 助手查图纸（`get_sheet`）都按这一套给：

| 地方 | 以前 | 现在 |
|---|---|---|
| 看图识别（`bidbench/spec/schema.json`） | 每项 0–1 的分数；来源分文字层、图像、两者 | 分数换成高中低：0.85 及以上为高，0.6 以下为低（和“图签把握低”是同一条线），中间为中；来源写“看图识别”，注明是 PDF 文字层还是图像。识别结果本身照原样存，只在显示和判断时换算 |
| 一级识别（`names.py`） | 高、中、低，带来源 | 不变，补上出处 |
| 事实（`state.py`） | 两张以上图说法一致为高，只来自 PDF 文字为中，只来自一张图的看图结果为低；另有人工确认、冲突 | 不变 |
| 智能分类（`classify.py`） | 不标 | AI 推测（专业、可能的内容、小类）一律算低 |
| 人工决定 | — | 人工定的现行版标“已确认” |

按规则推出来的项，把握跟着它的依据走：

- 楼层从图名推的，跟图名的把握；英文的 Level 几是第几层要看全项目怎么数，最多算中。
- 专业按图号认：ISO 角色代码、中文前缀（建施、结施）算高，只凭英文首字母（A-101）算中；看文件夹认的算中。

## 4. 第 0 层：文件本身

| 字段 | 例子 | 用来 |
|---|---|---|
| 文件名、所在文件夹 | `结构/结施-03 二层梁配筋图.pdf` | ①层推测、找原文件 |
| 格式 | PDF、DWG、图片 | CAD 文件按图号并到同一张图上 |
| 大小、页数 | 2.3 MB，12 页 | 估算识别花费 |
| 文件指纹 | SHA-256 | 判断两个文件是不是同一个、找重复文件 |
| 收图批次、收图日期 | 第 3 批，2026-03-01 | 本批新增、本批升版（不参与定现行版） |
| 压缩包里的位置 | `第3批.zip / 结构 / …` | 找原文件 |
| 风险 | 可执行文件、带宏的文档 | 文件安全检查 |

| 类别 | 要记的 | 用来 |

| 图纸目录 | 列出的每张图：图号、图名、版次 | 查漏图、核对目录版次 |

## 8. 推出来的结论

现行版、旧版、作废、缺图、版本冲突、目录和实际对不上、文件名和图签对不上、同层图纸、通用图、
受哪张变更单影响、被哪些图引用、事实冲突。这些都不存，每次重新算。

哪些结论能用哪一层：

| 结论 | 能用 | 不能用 |
|---|---|---|
| 现行版、缺图、作废、版本冲突 | ③图签、目录、变更单、人工 | ①②只能提醒，不能下结论 |
| 找图、分组、图谱、思维导图 | 任何一层，标出把握 | |
| 导出现行图纸 | ③识别过或人工确认过的图 | 只按名字暂定的图不导出 |
| 事实冲突 | ④读出的数值 | 按图名推测的数值不报冲突 |

拿不准的判断（版本、作废、冲突、塔楼归属）不自动拍板，列成问题并给出选项。

## 9. 规则

### 9.1 塔楼

1. 取值：项目里实际有的各栋（T1、T2……）；裙楼、地下室各算一栋；全项目通用的图（总图、总说明）归“公共”。
2. 同一栋楼的几种叫法（Tower 1、T1、1#楼）并成一个：软件先列出候选，你确认一次。
3. 看不出是哪栋时：
   - 同一个图号只在一处出现：放进“未分塔楼”，把握低。
   - 同一个图号在几栋楼都有，又分不清这份文件是哪栋的：列成问题让你指定。
4. 以前按图号做过的决定（以哪版为现行、采用哪份文件等），加上塔楼后要原样带过去。

怎么认，从可靠到不可靠：人工指定 > ISO 图号的分区代码（ZZ、XX 不算）> 文件夹名（T1、Tower 1、塔楼1、1#楼、A座、裙楼、
地下室、公共）> 文件名和图名里写明的“1#楼”“Tower 1”“A座” > PDF 文字里的“子项名称”。文件名、图名里不认单独的 T1
（也可能是版次），也不认“裙楼”“地下室”（图名里多半说的是楼层，如“地下室顶板平面图”）。同一个文件放在几栋楼的文件夹里，
算“公共”。Tower 1、T01、塔楼1 自动并成 T1，1号楼并成 1#楼；T1 和 1#楼 这种不同写法是不是同一栋，问人。

按楼各算各的：版本链；缺图（目录列出的、引用的、编号断号）；目录版次核对；楼层覆盖（每栋按自己图纸里出现的最高楼层查，
裙楼、地下室、公共只查断档）；同层图纸。引用公共的图照样找得到；只有别的楼才有的图，算这栋楼缺。

还是全项目一份的：从图上读出的事实（层数、高度……）。多栋楼层数不同时会报事实冲突，以后再分楼。

### 9.2 现行版：先比版次，版次一样再比日期

1. 版次高的是现行。版次按各自的写法排：P01 < P02 < C01（P 初步、T 招标、C 合同施工），A < B，第1版 < 第2版。
2. 版次一样（或都没写）、内容却不一样时，日期晚的是现行：
   - 版次一样的，问题中心照样提醒“改了图没升版”，投标时可能要提答疑；
   - 日期也一样或没有日期，列成问题让你选。
3. 版次和日期打架（版次高的日期反而早）：列成问题。
4. 同一张图混着两种版次写法（既有 B 版又有 P02）：版次没法比，按日期；没有日期就问你。
5. 日期优先用修改记录里这一版那一行的日期，没有修改记录才用图签上的出图日期
   （不少图签上写的是第一次出图的日期，升版后不改）。
6. 收图批次先后不参与定现行版。后收到的反而是旧版时，默认版次高的为现行，问题中心提醒你核实（可能是新版作废、退回旧版）。

补充：同一版次几份内容不同、修改记录又没跟着改（几份的修改记录日期一样）时，再比图签日期。
人工定过以哪版为现行的，不再提这几类问题；人工选过采用哪份文件的，按选的。

问题中心里：拿不准的（版次和日期对不上、版次写法不同或没写又比不出日期、同版次同日期内容不同）是“版本冲突”，算严重问题；
“改图未升版”“后收到的反而是旧版”是提醒，现行版已经按规则定了。

### 9.3 楼层：保留原叫法，再换算

1. 每张图记两样：原叫法（Level 05、L30、五层、Ground Floor）和换算出的第几层，显示成“Level 05（6F）”。
2. 按塔楼分别换算。“同层图纸”只找同一栋的同一层；地下室这种几栋共用的楼层，和每一栋的同层都算同层。
3. 换算规则（Level 00 是不是首层，Level 01 是 1F 还是 2F）软件先猜、写明理由，每个项目让你确认一次；各栋叫法不同时按栋确认。
4. 夹层、避难层、设备层、转换层、屋面不另加标签：原叫法里写着的照样显示；换算时夹层排在上下两层之间。

补充：没有 Level 01、1st Floor 这类写法（也没有图号里 01、02 这样的楼层代码）的项目不问。确认之前，这类楼层的把握最多算中；
确认之后跟着图名的把握。问题中心里是“楼层数法”，选项里软件猜的那个排在前面。

### 9.4 投标特有的字段

先加两个，以后想到再补：

- 工作包、标段：从文件夹名、图号、图签里读。
- 出图状态：招标用、仅供参考、施工用（ISO 的 S2 仅供参考、S4 阶段审批这类）。

### 9.5 图号格式：每个项目认一次，你确认后才用

图号怎么分段，各项目不一样。ISO 19650 英国附录的顺序是 项目-发起方-分区-楼层-类型-角色-编号（`PRJ1-ARC-T1-05-DR-A-1001`）；
也有 项目-单位-楼栋-专业-类型-楼层-流水号、后面再跟两位版次的（`PRJ1-ORG-T1-ST-DWG-GF-1202-00`）。按固定顺序去读，
专业、楼层、楼栋会读错或读不出，带不带版次后缀的同一张图会算成两张。所以每个项目先认出自己的图号格式：

1. 软件汇总：文件名里四段以上的图号按段数分组，每一段出现过哪些值、各多少个文件，每个值附例图名和页面编号；
   再加上文件夹目录的概况。只用文件名和文件夹名。
2. 软件先猜一个格式：看每一段的取值像什么（ST、AR 像专业，GF、01、XX 像楼层，DWG、DET 像类型，只有一个值的是项目代码，
   流水号后面再跟的两位数字是版次）。把握低。
3. AI 助手（Codex）读汇总，说出每一段是什么、每个代码什么意思、项目里有几种格式，写成一条“图号格式”提议。
   看不懂的代码按这个顺序找答案：例图名 → 目录页和这个代码的一两张图的 PDF 文字（只发文字）→ 列出要看图识别的几页，
   由你点开始（会把这几页发给 OpenAI）→ 都找不到，写成拿不准的问题。每个代码的意思写明是从哪看出来的。
4. 软件拿格式套一遍所有图号：套得上多少个文件、哪些套不上、哪些代码没有说明，附在提议上。
5. 你确认（问题中心的“图号格式”，或“AI 助手提议”），也可以选“先不用”。确认的格式记成人工决定。

问题中心的“图号格式”只在有 10 个以上四段以上的图号、又不是 ISO 英国附录写法时出现。

确认之前，格式只用来分组显示：按图号认不出专业（“其他”）的图用格式里的专业（把握低），图名里看不出楼层的用图号里的楼层代码，
小框按类型代码分。楼栋、图纸身份、缺图、版本都不受影响。

确认之后：

- 楼栋按图号里的楼栋段（人工指定的除外），码表里写“公共”的归公共。这种图号本身带着楼栋，图纸身份仍只写图号，不加“T1 · ”。
- 末尾的版次段从图号里拿掉，记成这份文件的版次（来源“文件名”）：`…-1007` 和 `…-1007-00` 是同一张图。
- 图号各段照原样，前导零保留（`0002` 不再变成 `02`）。以前按旧写法做的决定原样带过来。
- 专业按专业段的码表，把握高。专业多了三类：消防、智能化（通信网络、安防、音视频、楼宇自控）、岩土。
- 楼层按楼层段的码表换算：XX 不分层，GF 首层，01 这类按 9.3 的数法，LR、UR 这类按码表写的（写成屋面就算屋面）。
- 类型段按码表分图类：DET 详图大样、SCH 表格、SPEC 规格书、CAL 计算书。
- 以后收到的图号套不上（新的段数、新的代码），问题中心提醒，可以让 AI 助手补充，补完再确认一次。

没有确认格式（或选了“先不用”）的项目照旧按 ISO 19650 英国附录的顺序读。

### 9.6 图纸之间的关联

给 AI 建模找图用：从一张图出发，知道还要看哪些图、看那张图的哪一块。关联都从④看图识别来（目录列出从目录来），
每条带原文、出处页面和位置，不存库，每次重新算。

| 种类 | 图上长什么样 | 编号 | 指向 |
|---|---|---|---|
| 详图索引 | 圆圈中间一道横线，上面详图编号、下面详图所在图号；或写成 ⑤/建施-12 | 详图编号（5） | 那张图上编号相同的详图（有就带位置） |
| 剖切 | 剖切符号两端的编号，旁边注明剖面在哪张图（1-1 剖面见建施-05；英文图是 301/1，图号在前） | 剖面编号（1-1） | 那张图上同名的剖面 |
| 立面 | 立面索引符号（英文图 201/1 指 A-201 的第 1 个立面） | 立面编号 | 那张图上同编号的立面 |
| 文字引用 | “详见建施-08”“未注明者详见结施-01”“大样见建施-09”“REFER TO A-301” | 没有 | 整张图；只写了单位没写图号的（REFER TO 某院 DRAWINGS）不连线，原文留在识别结果里 |
| 变更涉及 | 变更单、答疑条文里写到的图号（“结施-03 二层梁配筋图：……”“建施-07 ② 女儿墙大样：……”） | 写到详图编号就带上 | 被改的图；这张图状态变成“有变更单” |
| 目录列出 | 图纸目录的一行 | 没有 | 只在缺图时作为关联 |
| 共用参照 | DWG 里绑定的外部参照名一样（同一个核心筒、同一套柱子被几层的平面共用） | 参照名 | 用了同一个参照的图，不分方向 |
| 同层、通用图 | 不画在图上，按楼层、图类推出来 | 没有 | 整张图 |

- 指向别的专业的图叫跨专业，种类不变。
- 剖面图上的楼层标高表（Level 05 - 18.00 m）记成关键数值，给楼层换算当证据，不算关联。
- 引用带编号、被指的图上又读出了同编号的详图（或同名剖面）时，关联带上那块详图的位置，找图工具可以直接跳过去；
  编号对不上的照样保留关联，只是不带位置。
- 分区、轴线范围：一层平面拆成几张图（A 区、B 区，或 1~12 轴、12~24 轴）时，同层的图按分区和轴线范围区分，
  建某一块时先看管那一块的图。读不到时为空，不猜。
