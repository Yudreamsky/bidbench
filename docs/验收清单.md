# 验收清单

给验收员（Codex，或者人）逐项核对用。运行 `python tools/codex_accept.py` 会让 Codex 在一个临时的代码副本里按这份清单实际操作，
写出验收报告；也可以照着清单手动做。

规则：

- **只验证，不修改**：不改代码、文档、测试，不提交，不推送。发现问题写进报告。
- **只用合成数据**：图纸只用 `samples/make_sample.py` 生成的样例（`samples/out/`），不要打开任何真实项目、真实图纸。
- **不花钱、不占额度**：不调用 Claude API，不真的用 Codex 识图（只做 `--dry-run` 估算）。
- 临时文件都放在副本里的 `.accept-tmp/` 下。例外：演示脚本 `samples/run_demo.sh` 固定把样例生成到 `samples/out/`
  （已在 `.gitignore` 里），照原样运行即可，不用改写脚本。
- 在 Codex 里验收时，收图的 Windows Defender 扫描可能报 `0x80508023`（Codex 的运行环境连不上杀毒服务），
  程序会提示“扫描没有完成”并照常做静态检查，这不算不通过；其他错误照常记为问题。
- 每一项写清楚：结果（通过 / 不通过 / 无法验证）、证据（运行的命令和关键输出）、发现的问题。

## A 基础

- **A1 全部测试通过**：`python -m pytest -q`。全部通过才算通过；有失败的写出失败的测试名和原因。
- **A2 演示流水线**：`bash samples/run_demo.sh .accept-tmp/demo`。命令成功结束；`.accept-tmp/demo/reports/` 里有图纸台账、缺图清单、
  答疑问题清单、项目事实、文件安全检查；`.accept-tmp/demo/exports/` 里有现行图纸文件夹和 `mirror/`。

## B 收图

- **B1 三种收图方式**：用 `python samples/make_sample.py .accept-tmp/samples` 生成样例，新建一个项目，分别收一个压缩包、
  一个文件夹（`1020补充`）、同时收两个文件（算同一批）。每次都成功，`bidbench log` 里能看到三次收图。
- **B2 重复收图被拒**：同一个压缩包再收一次，命令失败，提示已经作为某个批次收过了。
- **B3 风险文件**：A2 的演示项目里，`0915修改.zip` 带的 `acad.lsp` 等无害占位文件被登记为高风险（看收图输出或
  `reports/文件安全检查.md`）；`exports/` 的现行图纸文件夹里没有这些文件。

## C 台账与问题

- **C1 问题都能发现**：A2 的演示项目里（`bidbench -p .accept-tmp/demo build` 的输出或 `reports/`）能看到缺图（建施-10、建施-11）、
  版本冲突（电施-01）、作废还是漏发（建施-05）、目录版次（建施-06 目录写 B 版、手上只有 A 版，严重；
  结施-00 目录上的版次没跟上图纸，提醒），答疑问题清单里有建施-06 那一条。
- **C2 人工决定生效**：`bidbench -p .accept-tmp/demo decide sheet_void 建施-05 voided` 之后再 `build`，建施-05 那条
  “作废还是漏发”问题消失；它属于“提醒”，所以提醒数少 1，严重问题数不变。

## D 日志

- **D1 操作日志**：`bidbench -p .accept-tmp/demo log` 按时间列出新建项目、收图、识别、计算报告、导出，以及 C2 的决定；
  故意收一个不存在的文件，再看 `log`，这一条标“出错”并写明原因。
- **D2 排错日志不记密码**：收图时加 `--password 验收口令123`，之后在排错日志文件夹（`bidbench log` 最后一行给出位置）
  的日志里搜索，找不到 `验收口令123`，命令里写成 `***`。

## E 工作台接口

- **E1 本机接口和令牌**：`bidbench -p .accept-tmp/demo serve --port <空闲端口>` 启动后（测完要关掉）：
  `GET /api/state`、`GET /api/log` 返回 JSON；`POST /api/decision` 不带 `X-Bidbench-Token` 头返回 403；
  `GET /api/state` 带一个别的 `Host` 头（如 `evil.example`）返回 403。

## F 识别

- **F1 模拟识别**：A2 之后，`bidbench -p .accept-tmp/demo log` 里每批都有模拟识别，`reports/图纸台账.md` 里的图纸有图名。
- **F2 Codex 估算**：`bidbench -p .accept-tmp/demo recognize --executor codex --scope all --dry-run` 生成任务包并输出
  “预计约 N 分钟”，不实际调用 Codex。
- **F3 识别结果格式**：抽一个任务包 `results/pages/` 里的结果文件，用 `bidbench/spec/schema.json` 校验通过
  （可以用 Python 的 jsonschema）。

## G 安全约束（只读检查）

- **G1 工作台不加载外部资源**：`bidbench/web/index.html` 里没有从 `http://` 或 `https://` 加载的脚本、样式、字体、图片。
- **G2 没有真实病毒特征**：`git grep -n "STANDARD[-]ANTIVIRUS-TEST"` 没有结果（方括号让这条命令不会搜到清单自己；
  只搜这一段，不要在命令或文件里写出完整的特征串，否则会被本机杀毒软件拦截）。测试里假的扫描输出中出现的威胁名
  （如 `EICAR_Test_File`）不算。
